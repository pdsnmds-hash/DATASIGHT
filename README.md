# DATASIGHT Prompt Builder

Нативный Android-проект на Kotlin и Jetpack Compose. Минимальная версия Android 8.0 (API 26), compile/target SDK 36. Приложение формирует промпты локальными правилами; обращения к модели, сетевого стека, регистрации, аналитики и INTERNET permission нет.

## Запуск и сборка

1. Откройте корневую папку в Android Studio.
2. Установите Android SDK Platform 36 и JDK 17 или 21. Укажите свой SDK через Android Studio либо `sdk.dir` в локальном `local.properties`.
3. Дождитесь Gradle Sync. Первое получение зависимостей требует интернета на машине разработчика; установленное приложение работает офлайн.
4. Запустите `app` на устройстве API 26+.

```sh
./gradlew testDebugUnitTest assembleDebug
```

Сборка `assembleDebug testDebugUnitTest` успешно выполнена 2026-11-03 после открытия доступа. APK: `app/build/outputs/apk/debug/app-debug.apk`, копия для передачи — `artifacts/DATASIGHT-Prompt-Builder-debug.apk`. Установлен и запущен на эмуляторе `DATASIGHT_API36` (Android 16/API 36). 134 Gradle unit tests пройдены. Фактические проверки перечислены в [docs/VERIFICATION.md](docs/VERIFICATION.md).

Включён настоящий Gradle wrapper JAR, Unix- и Windows-скрипты. Зависимости закреплены: AGP 8.13.2, Gradle 8.14.3, Kotlin/Compose compiler 2.2.20, KSP 2.2.20-2.0.4, Compose BOM 2024.12.01, Room 2.8.5, Navigation 2.8.5, DataStore 1.2.1.

## Работа с приложением

Первый запуск — на французском при любом языке устройства. Settings/Paramètres переключает весь встроенный контент на English или Français. Тема следует системе, доступны светлая и тёмная. Для каждого нового промпта язык ответа берётся из текущего языка UI; далее он изменяется отдельно на третьем шаге. Введённые пользователем тексты не переводятся.

Создать → категория → подтип и задача → контекст → формат → результат. Формы отличаются по категории: стек/входы/выходы/проверки для кода, критерии/сравнение для анализа, разделы/цель для документов, количество/отбор для идей. Непустые поля и инструкции выбранного шаблона попадают в промпт. JSON может иметь явно заданную структуру.

В результате можно редактировать текст, копировать, сохранить под названием, вернуться в форму и поделиться через Android. Повторная генерация после ручной правки требует выбора: заменить или сначала сохранить отдельную версию. Сохранённый текст при открытии не пересобирается из новой версии шаблона.

«Мои промпты» содержит сохранённые записи и отдельный фильтр черновиков. Доступны поиск, фильтр категории, избранное, дублирование, удаление с Snackbar Undo и UTF-8 TXT через системный выбор файла с предпросмотром текста. Незавершённые записи автоматически сохраняются в Room, включая шаг, исходник, параметры и редактируемый результат.

60 локальных шаблонов: по 10 Write, Analyze, Document, Ideas, Develop, Improve. У каждого стабильный ID, FR/EN название, описание, применение, собственное поле с примером, инструкция, заполненный пример промпта, советы и теги. Полный состав — `app/src/main/assets/templates.json`. Предпросмотр показывает итоговую структуру до применения.

## Архитектура

Один модуль `app`, ручное создание зависимостей, без DI-фреймворка:

- `Core.kt`: неизменяемые сериализуемые модели, `PromptComposer`, `FormValidator`, `BackupValidator`, централизованные контакты и корпоративные тексты.
- `Fields.kt`: определения специфических полей категорий, без зависимости от Compose.
- `Data.kt`: Room entities/DAO/database, DataStore, AndroidViewModel, StateFlow и корутины. Room — источник истины для записей; StateFlow держит текущую форму. Запись после паузы 180 мс и дополнительный flush при уходе приложения в фон.
- `MainActivity.kt`: семантические Material 3 палитры, оболочка Navigation Compose и предпросмотр.
- `LibraryScreen.kt`: библиотека по референсу, поиск, фильтры, избранное и адаптивные карточки; отчёт `docs/LIBRARY-REDESIGN.md`.
- `HomeScreen.kt`: главная по пользовательскому референсу, адаптивная сетка, Canvas-иллюстрация и нижние вкладки. Детали проверки: `docs/HOME-REDESIGN.md`.
- `Builder.kt`: три шага и подтверждение повторной генерации.
- `Actions.kt`: редактор, настройки и SAF backup.
- `CompanyScreen.kt`: DATASIGHT по референсу, описания услуг, контакты и предпросмотр обращения; отчёт `docs/COMPANY-REDESIGN.md`.
- `SavedScreen.kt`: пользовательские записи, реальные Room-счётчики, поиск, категории, сортировка, действия и TXT; отчёт `docs/SAVED-REDESIGN.md`.
- `CoreTest.kt`: целевые и параметризованные unit tests.

В записи хранятся ID, название, категория, подтип, сериализованные структурированные параметры, итоговый текст, язык, даты, избранное, ID шаблона и признак черновика. ID не зависят от перевода.

## Резервная копия и приватность

Настройки → JSON export/import через Storage Access Framework. Формат: `schemaVersion: 1`, `records`, `settings`. Максимальный размер 20 MB и 10 000 записей при импорте. Перед записью проверяются JSON, версия, IDs, категории, даты, структурированные параметры и допустимые настройки. Затем показываются количества записей и подтверждение полной замены. Ошибка чтения/валидации не вызывает запись.

Замена записей и журнал настроек записываются одной Room-транзакцией. DataStore находится в отдельном хранилище: после коммита применяется журнал; при прерывании процесса он повторяется при следующем запуске. Таким образом прерванный перенос настроек можно завершить без частичной замены записей. Облачный Android backup отключён целиком через `allowBackup=false`; ручной JSON не зашифрован.

## Проверка без Gradle в текущей среде

`python3 tools/verify_local.py` — вспомогательный, привязанный к локальному macOS-кэшу компиляторный прогон. Он компилирует весь Kotlin, включая UI, с Compose и serialization compiler plugins и запускает настоящий JUnit. Это не переносимый заменитель Gradle: classpath собран из имеющихся AAR/JAR, транзитивное разрешение Gradle, генерация Room через KSP, Android linking/dexing и запуск на устройстве этим не проверяются.

Для снимков на работающем эмуляторе откройте нужный экран и вызовите `tools/capture_screenshot.sh fr-light-create` (затем повторите для обеих тем, языков и ключевых экранов). Реальные снимки первого запуска, обеих тем, EN/FR и отдельных экранов находятся в `docs/screenshots`.
